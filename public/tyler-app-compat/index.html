Paste this into your Claude: building apps compatible with Matt's app system

Build every app so it follows these conventions. They are the cheap part of Matt's system; the shared code kit (hud-kit) is not available to you yet.

  1. Components, base plus skin. Each UI piece is a "base" (geometry, layers, behaviour) and a separate "skin" (looks). Bases meet five points:
    • Knobs declared in code: {v, min, max, step, note} per knob, keyed <component>.<knob>. Every size, gap, width and timing is a knob; no magic numbers.
    • Tuned live: changing a knob applies within a second, no reload.
    • Registers itself as an "Edit mode piece" (name plus its knobs), as a harmless no-op when no edit mode exists.
    • Skinned, not styled: base CSS uses only --<name>-* variables.
    • Catalogued: one README line per component, plus a light and dark preview and a test.
  2. Colour by role, never hard-coded. Define role tokens (surface, text, accent, danger) once; skins map them to the --<name>-* variables.
  3. Feel knobs in one tweaks.json. Timings, fades, sizes and colours live there, each with default, min, max, step and a one-line note.
  4. Light and dark always. Light default; dark follows system appearance. Check both.
  5. Self-update with a build stamp. The app shows its version and build, and offers Update (never mid-playback or mid-task).
  6. Good macOS citizen. List every command in one place and build the menu bar from it, each with its shortcut, so Help-menu search finds it.
  7. Edit-mode-ready. Expose sidebar widths, gaps and card sizes as knobs, so a drag-handle mode can later write the same tweaks.json.

Keep it plain Markdown and model-neutral; nothing here needs Matt's Mac.
