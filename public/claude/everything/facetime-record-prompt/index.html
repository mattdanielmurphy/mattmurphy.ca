Ask to record FaceTime calls (2026-10-26)

15:00 Record-this-call prompt

What Matt asked: when a FaceTime call starts, ask whether to record the transcript (unless one is already running), and let him pick or type who the call is with. Keep the watcher light; make it live.

What already existed: ~/.hammerspoon/modules/call_transcript.lua was meant to start call-transcript automatically when a FaceTime call window appeared. It looked for a FaceTime window titled with the other person.

Old watcher never saw calls

During today's call with Tyler the FaceTime window was still titled just "FaceTime", so the old title check never fired. Today's recording was started some other way (likely the ⌃⌥⌘R hotkey). The window's accessibility tree does show the call: three levels down there is an element named "FaceTime Video call", then a button titled with the other person ("Tyler Murphy"), and the End button (leaveButton). The End button vanishes when the call controls auto-hide, so the watcher keys on the "FaceTime … call" element and treats the End button as a backup.

Watcher stays light

Every 3 seconds (tweakable), and only while FaceTime is open, it reads the top three levels of the FaceTime window: about 20 accessibility reads, measured at 15 to 22 ms. A 0.5 s AX timeout means a busy FaceTime can't stall Hammerspoon. No new process, no launchd job. Rejected: watching the mic or "Audio and Video Controls" menu extra (fires for Audio Hijack, Ableton and dictation too), and a Swift CoreAudio helper (an extra process for no gain).

How the prompt works

After two checks in a row see a call, and only if no transcript is running, a Hammerspoon chooser opens: "FaceTime call: record it? Type a name or pick one (Esc = no)". Rows: the FaceTime caller's name, recent callers from ~/calls/ file names, then "Don't record this call". Typing a name adds "Record call with <name>" at the top. Rows that would save to the same file (Tyler Murphy and Tyler) are listed once. It asks once per call and closes itself after 90 s. Picking a name runs call-transcript start <first-name> --left <Name> --right Matt. When the call ends it runs call-transcript stop, but only for a transcript it started; that ownership is kept in ~/calls/.transcript.owner, so a Hammerspoon reload mid-call still stops it.

Untested parts

The chooser itself hasn't been shown yet: Matt was on a call and it would have popped up over it. Detection, name, row list and the unit tests were all checked during the live call. An incoming call that hasn't been answered yet doesn't count as a call; the prompt comes once it connects. Audio-only calls are assumed to read "FaceTime Audio call" (the match is FaceTime <word> call).

Knobs: ⌃⌥⌘T → "Call transcripts": poll rate, debounce, prompt timeout, how many recent callers.
