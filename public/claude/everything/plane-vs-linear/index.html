Plane vs Linear (2026-10-27)

18:05 Should Matt switch from Linear to Plane?

Matt is leaning toward Plane because Linear's free plan would need paying sooner. The earlier thread ("Organize Linear board and compare free options") found Linear Free = 250 issues and 2 teams, with ~39 cards used, and Plane self-hosted needing ~4 GB RAM. This section checks Plane's limits and agent access properly and recommends a path. Nothing has been migrated.

Plane free cloud limits

From plane.so/pricing, checked today:

  • 12 users, and no stated cap on projects, work items or storage. That beats Linear's 250-issue cap.
  • Importers included on Free: Linear, Jira, Asana, ClickUp, CSV.
  • Not on Free: exports, integrations (GitHub, Slack, etc.), wiki/nested pages, page templates, active-cycle features.
  • Paid (Pro): $6/user/month yearly or $8 monthly. Linear Basic is $10/month for one person.

The "no exports" gap matters less than it looks: the API and MCP can read every card out, so an agent can always dump the board to JSON/Markdown if Matt ever wants to leave.

Self-hosting on the VPS

  • Plane Community Edition is free but is a stack of containers (web, API, worker, Postgres, Redis, MinIO). Third-party guides say 4 GB RAM minimum, 8 GB recommended. Plane itself publishes no number I could find.
  • The Linear importer is not in Community Edition; Plane's docs list it only on Cloud and the paid Commercial Edition. Self-hosting would mean a CSV or API-script migration.
  • Per the VPS rule (ask before heavy installs), this is a heavy install. Rejected for now: free cloud already removes the issue cap, so self-hosting adds work and VPS load for no gain.

Agents can use Plane

  • Official MCP server: makeplane/plane-mcp-server, hosted at https://mcp.plane.so/http/mcp with OAuth sign-in, so it can be added as a Claude connector like Linear's. About 30 tools covering work items, cycles, modules, labels, states, members.
  • REST API with personal access tokens; official docs say 60 requests per minute per key. Plenty for agent use.
  • I didn't find anything saying the API or MCP is blocked on the Free plan, but I haven't tested it. First migration step is to confirm it works.

Recommendation

Switch to Plane Cloud Free, not self-hosted. Why: no issue cap, a built-in Linear importer, and an official MCP so agents keep working. Trade-offs: no exports button (API covers it), no GitHub/Slack integrations (Matt isn't using them), and Plane's UI is a bit busier than Linear's.

Rejected: staying on Linear (fine for months, but Matt wants room and would split Slub into a second workspace anyway); self-hosting (heavy VPS load, no importer).

Fits the project freeze: it replaces a tool rather than adding one, and the Linear board gets archived.

Migration plan

  1. Matt signs up at plane.so (an account is his to create) and makes a workspace. Slub can be a second workspace later.
  2. Add Plane's MCP as a connector and confirm agents can read and write a test card.
  3. Run Plane's Linear importer (Workspace settings > Imports > Linear) with a Linear personal access token. It brings states, labels, comments, attachments, cycles, and Linear projects (as Plane modules). Non-parent issue links don't carry over.
  4. Check the ~39 cards, columns (Idea / Planned / Live on Mac / Paused / Done) and the "Parked idea" label (MAT-35..42) landed.
  5. Update the rules that point at Linear (.rules/ thread-cleanup rule, linear-board memory) to Plane.
  6. Leave Linear read-only for a couple of weeks, then archive it.

Undo: Linear stays untouched until step 6, so stopping at any point loses nothing.

Sources: Plane pricing, Plane Linear importer, Plane MCP server, Plane API docs, Railway Plane template (RAM figures).

18:05 Two boards: personal and Slub (shared with Tyler)

Matt wants one board for himself and his life, and one for Slub shared with Tyler, with room to add people later.

Two Plane workspaces

  • Make two separate Plane workspaces: "Matt" (personal, only Matt) and "Slub" (Matt + Tyler). One Plane login switches between them, like Slack workspaces.
  • Why two workspaces and not one workspace with private projects: Tyler can never stumble into personal cards (health, school, money), and each workspace has its own plan and bill, so Slub can upgrade or pay later without touching the personal one.
  • Rejected: one workspace with project-level privacy. It works, but one wrong share setting exposes personal cards, and billing would be mixed.

Adding people later

  • Plane's free plan allows 12 users, and plans are per workspace, so the Slub workspace can grow to 12 people for free. Personal workspace stays at 1.
  • People join by email invite from workspace settings; roles are Admin, Member and Guest.
  • Past 12, Pro is $6 per user per month (yearly). Linear's free plan has unlimited members but a 250-card cap per workspace, which a growing team would hit first.
  • Not verified: whether guests count toward the 12.
