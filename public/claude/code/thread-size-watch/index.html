Thread size watch

17:50 Catching big threads you drive yourself

You said a design thread passing 600k meant the coordinator and the hooks both failed, and that the fix must not give you a job. Now any thread past 250k gets a fresh start by itself at a natural break, and you keep typing in the same sidebar thread.

A new thread was not possible

The brief asked for a handoff and a new thread. The app won't allow that: it starts a session only from words you typed to that session, and it refuses on an automated note. That's the same wall the earlier cold-thread work hit. I read the app's own check to confirm it.

I could have made the wake-up look like you typed it, the way button presses do, but that would be faking your words to get around the app's check, so I didn't. A proposal card would have needed your click. So the move happens in place: the coordinator writes the handoff, and the thread compacts itself and keeps your next steps. You see a compaction line in the thread, and nothing else.

How it decides

A small job runs every minute and reads each thread's real size from disk, so it needs nothing from the thread. Past 250k, it waits for a natural break: the reply finished and five quiet minutes. Then it wakes that thread's coordinator. If nobody owns the thread, or its coordinator isn't running, the central Coordinator gets it.

Just before compacting, the thread checks again. If you've started typing, even with nothing sent, it waits for the next break. If the cache has gone cold it also waits, so it never pays full price. Both numbers are knobs in the Tweaks panel under Context alert: thread.limitTokens and thread.breakMinutes.

Three other things were wrong

The size script read the pre-compaction number after a thread compacted. That's the stale 370k from the commit you pointed at. Seven recent threads read high, some wrongly refused by the send guard. Fixed.

The fix that removed the Code-thread hold (0.7.12) was committed but never installed, so the old 0.7.10 hold was still live. 0.7.13 is installed now and carries that fix.

The mod still showed a "consider /_handoff" toast at 250k, which is exactly the hook telling you to do something. Removed.

Decisions you might veto

Compaction keeps a summary rather than a clean slate. It's slightly less of a reset than a new thread, but it's the only version that needs nothing from you.

Five minutes is my guess at a natural break. Too short and it compacts while you're reading a long reply; your message would then wait about a minute. It's a knob, so it's easy to change.

What isn't proven

Mod updates reach a thread only when its process restarts, so threads running right now keep 0.7.10 until then. Until they do, they only get the old 50-minute idle compaction.
