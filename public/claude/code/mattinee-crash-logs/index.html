03:05 Why Mattinee keeps closing

You asked why the app keeps crashing and whether crashes were recorded.

Cause

All 16 exits Android kept (01:55 to 02:24 on 2026-10-31) were 11 force-stops and 5 installs. There were no crashes, freezes or memory kills, and the crash buffer was empty. Android keeps only the last 16 exits, and the rename to ca.mattmurphy.mattinee cleared older history, so earlier closures can't be checked directly. The app also reopens itself after an update.

Fixes

Version 0.3.58: crashes stay saved until the server accepts them (they were deleted before sending). The catcher starts with the process, not only with the main screen. Freezes, native crashes, memory kills and on-screen closures now come from Android's exit history. auto-install.sh waits while the app is on screen and the Streamer is awake. dev.sh does not wait.

Test

am crash at 02:59 reached the Mac log and the VPS as Crash: CrashedByAdbException. A force-stop was logged as Closed:. Both test lines remain in the log. Freeze, native and memory reports were not triggered for real.

Deploy mistake

I ran the zsh-only deploy/vps.sh with bash, so it ran rsync from / with --delete for 22 minutes. I killed it. The VPS showed 0 changed files, so nothing landed and nothing was deleted. vps.sh now works in either shell.
