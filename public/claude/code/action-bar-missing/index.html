18:15 The band above the prompt went missing

You said the actions bar and read-aloud settings had vanished from the Code tab. It's back in every running thread, and you didn't have to restart anything.

Why the band vanished

The read-aloud mod draws the band, and the action buttons sit in the same row. Its layout included one sizing setting, minWidth, around the spot where Claude's own band content goes. Claude refuses a layout like that and throws away that mod's whole drawing without showing any error. The result is an empty band in every thread.

Your Mattinee Coordinator screenshot showed it, and a test session on the same Claude Code build the app runs gave the same refusal.

It was not the new thread-size watcher, the context-alert changes, a compaction or the thread move. It wasn't an app update either: the app bundle dates from Oct 29 and the Claude Code build hasn't changed.

What is still unexplained

That setting has been in read-aloud since Oct 30 at 14:00, yet the band was only reported missing tonight. The same code on the same build should have failed all along. I found nothing tonight that would change the result, and old logs don't record what the band drew. So I can't tell you whether it really broke tonight or had been gone longer. Either way the fix removes the cause.

The fix and how it was tested

I removed that one setting, so read-aloud is now version 0.9.8. Your band looks the same as before, because long action buttons wrap in the action bar's own row, not in the box that held the setting.

  • In the real engine: the speaker and mic came back, and a test reply with an Actions line drew both action buttons and the close button.
  • Bug put back on purpose: the check failed with the same refusal, so it does catch this. The fix went back in straight after.
  • Live on your screen: the speaker, mic and pause buttons reappeared in the Coordinator window right after the update, with no restart.

Not tested: clicking a button on screen. Nothing about clicking changed. Action buttons in your real window also weren't checked, because they only show after a reply with an Actions line.

So it gets caught next time

The mod's own tests passed through all of this because they use a stand-in for Claude's content. Read-aloud now has a test that uses the real kind, and it failed before the fix. There's also a new check that asks the real engine for the band, which any agent can run after changing a band. It doesn't touch your screen. The rule is written in the project notes.

To undo: revert the commit and run the plugin update again, though that brings the empty band back.
