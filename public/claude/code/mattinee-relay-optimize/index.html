Mattinee relay optimization

22:30 Why three streams buffered

Main cause: the watchdog added at 18:04 asked the relay /ping from 127.0.0.1. The relay refused non-tailnet addresses first (403), so the watchdog called it frozen and killed it every minute. 306 restarts logged by 22:10. Every restart cut all streams.

Memory: the 300 MB to 2.4 GB swing was fetch and Response buffering video for slow clients, repeatedly reset by those restarts. Local test with a 40 MB/s upstream and three slow clients: old about 1 GB, new about 100 MB.

Fix: /ping answers before the address check; /v joins sockets directly. Rejected: direct streams, node:http client and server (all still buffered in Bun). Chunked answers fall back to fetch.

Not tested: the Windows build has not run; real Real-Debrid traffic has not gone through it. The apply command checks https with one request and rolls back on failure.

Other gains: none worth doing until the dashboard is re-read after a few streams; CPU median 31%.

Undo: deploy/relay.sh undo (also disables the watchdog, which the old relay fails).
